# Тактирование и проверка Block1

Для варианта 12 выход ROM зарегистрирован, выход RAM — незарегистрирован
(`OUTDATA_REG_A = "UNREGISTERED"`). Незадействованный `outclock` RAM на схеме
оставлен неподключённым; режим выхода определяется параметром мегафункции,
а не только наличием подключения к выводу.

- При чтении ROM регистр адреса работает по фронту `clk`, а выходной регистр —
  по спаду. При чтении RAM её регистр адреса работает по спаду. Поэтому к
  следующему фронту `clk` данные успевают установиться на шине.
- Буфер принимает данные по фронту `clk`. Управляющий регистр готовности чтения
  вне буфера обновляется по спаду, чтобы не создать лишний фронт при включении
  разрешения чтения.
- При записи в RAM она принимает данные по фронту `clk`, а сдвиг буфера
  происходит по спаду. Сдвиг разрешён только пока активен `Write`.
- Последний байт принимается RAM на 370 нс и 730 нс соответственно. `Write`
  снимается на 375 нс и 735 нс, до следующего спада; поэтому шестой, уже
  записанный байт не сменяется старым на короткий интервал.
- В VWF адреса меняются через 2 нс после спада `clk`, а не в момент
  тактирования памяти. Тест проверяет не менее 8 нс между изменением адреса
  и следующим фронтом записи для данного тестового вектора. Сигналы режима
  `Read` и `Write` могут при этом оставаться активными: конкретная операция
  памяти определяется фронтом её тактового входа.

Проверки `python tools/check_bdf.py` и `python tools/verify_strict.py` —
структурная и идеализированная функциональная модель, не Quartus timing
analysis. После скачивания проекта в Quartus II 9.1 необходимо выполнить
Full Compilation, затем Generate Functional Simulation Netlist и Start
Simulation. Для физической схемы нужны также ограничения и timing analysis.
